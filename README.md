# Pablo Sánchez Serrano — personal website

A small, static Astro website presenting research and technical work in privacy and artificial
intelligence. It uses Astro components, strict TypeScript, a typed project collection and one local
BibTeX file. There is no CMS, database, analytics service or client-side framework.

The professional profile links, email address and publication records are populated. Remaining
biographical placeholders, the portrait and the PDF CV must be reviewed before launch.

## Requirements and commands

Use Node.js 22 or newer and npm:

```sh
npm install
npm run dev
npm run validate
npm run build
npm run preview
```

`npm run validate` checks formatting, runs the BibTeX tests, performs Astro/TypeScript diagnostics
and creates the production build in `dist/`.

## Where to edit content

- Personal metadata, profile links, email, CV path, image path and author-name variants:
  `src/config.ts`
- Homepage wording and background: `src/pages/index.astro`
- Research directions: `src/pages/research.astro`
- HTML CV: `src/pages/cv.astro`
- Publications: `src/content/publications.bib`
- Projects: `src/content/projects/`
- Global visual tokens: the first blocks in `src/styles/global.css`

The accent is controlled by `--color-accent`, `--color-accent-hover`,
`--color-accent-soft` and `--color-focus` in `src/styles/global.css`. Update both the light and dark
token blocks together. Components do not define their own accent palette.

Inter Variable is self-hosted through `@fontsource-variable/inter`. Inter was chosen for its neutral
technical character, strong small-size readability and broad range of weights without multiple
font requests.

### Replace the portrait

The profile photograph is stored at `public/images/profile.jpg`.
Then update `profileImage` and the descriptive `profileImageAlt` in `src/config.ts`. Keep explicit
image dimensions or the same 4:5 aspect ratio to avoid layout movement. A source image around
800–1200 pixels wide is sufficient for this layout.

### Replace the CV PDF

Replace `public/cv/pablo-sanchez-serrano-cv.pdf` while keeping that filename, or update `cvPath` in
`src/config.ts`. The HTML CV is edited separately in `src/pages/cv.astro`; the PDF is intentionally
not generated by the site.

### Add a publication

Add a normal BibTeX record to `src/content/publications.bib`. This file is the sole source of
publication metadata. Supported common types are `article`, `inproceedings`, `conference`, `misc`
and `preprint`; an unknown type is retained and labelled `other` rather than discarded.

Standard fields include `title`, `author`, `year`, `journal`, `booktitle`, `publisher`, `volume`,
`number`, `pages`, `doi`, `url`, `abstract` and `keywords`. The optional custom fields are:

- `pdf`
- `code`
- `project`
- `slides`
- `poster`
- `video`
- `selected`
- `category`

Set `selected = {true}` to include a record in the homepage and HTML CV selections. Authors are
separated with BibTeX `and`. Add any spelling used for Pablo to `authorNameVariants` in
`src/config.ts` so his name is highlighted. The parser deliberately reports malformed entries
during the build instead of skipping them.

### Add or publish a project

Copy `src/content/projects/example-private-pipeline.md` and rename it with a durable, URL-friendly
filename. Complete its frontmatter and Markdown sections. The schema in `src/content.config.ts`
validates title, summary, year, status, role, technologies, links, image and related-publication
identifiers.

- `draft: true` excludes the project from every production list and route.
- `draft: false` publishes it and automatically reveals Projects in the navigation.
- `featured: true` also makes it eligible for the homepage, which shows at most three.

Projects can represent software, datasets, benchmarks, pipelines or implementations attached to
research; they do not need to be standalone applications.

## GitHub Pages deployment

`.github/workflows/deploy.yml` runs on pushes to `main`. It installs the locked dependencies,
validates the project, builds `dist/`, uploads that directory and deploys it through GitHub Pages.

One-time repository setup:

1. Open **Settings → Pages** in `pablosanserr/pablosanserr.github.io`.
2. Under **Build and deployment**, select **GitHub Actions** as the source.
3. Ensure Actions are permitted under **Settings → Actions → General**.
4. Merge or push the reviewed site to `main` and watch the `Deploy to GitHub Pages` workflow.

No repository secret is required. The workflow receives the minimum `pages`, `id-token` and
read-only content permissions.

### Add a custom domain later

Set the custom domain in **Settings → Pages**, add the DNS records GitHub provides, and add a
`public/CNAME` file containing only the domain. Then change `site` in `astro.config.mjs`,
`siteUrl` in `src/config.ts`, and the sitemap URL in `public/robots.txt`. No component redesign is
needed.

## Themes, accessibility and JavaScript

The default follows the operating-system theme. The toggle stores an explicit choice in
`localStorage` and an inline head script applies it before rendering to avoid a theme flash.
Navigation and core content remain available without JavaScript. JavaScript only enhances the
mobile menu, theme choice, section reveals, publication filters and BibTeX copying.

The site includes semantic landmarks, a skip link, visible focus styles, keyboard-friendly
controls, reduced-motion support, responsive layouts and print styles for the HTML CV.

## Future additions

### Blog

Create a separate `posts` collection in `src/content.config.ts`, store posts under
`src/content/posts/`, and add list/detail routes under `src/pages/blog/`. The existing layout,
metadata and content-width classes can be reused; no current navigation or page needs redesigning.

### Analytics

No analytics are included. If they become necessary, prefer a privacy-preserving service, document
its data collection, load it once from `BaseLayout.astro`, respect consent requirements and measure
its performance impact before deployment.
